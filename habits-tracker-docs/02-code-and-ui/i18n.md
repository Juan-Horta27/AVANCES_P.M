# Internacionalización (i18n)

> **Estado actual: no implementada.** La app es monolingüe en español, con los textos escritos
> dentro de cada pantalla. Este documento describe la regla acordada y el plan para cumplirla;
> está registrado como deuda en el [DoD](../00-governance/definition-of-done.md) y en la
> [retrospectiva del Sprint 1](../00-governance/retros/sprint-01.md).

---

## Situación

Todo el texto visible vive incrustado en el JSX:

```tsx
<Text style={styles.titulo}>Habitos Saludables</Text>
setError('La contrasena debe tener al menos 6 caracteres');
Alert.alert('Eliminar habito', `¿Eliminar "${nombre}"?`, ...)
```

Además, los nombres de meses y los días abreviados están escritos a mano en
`src/utils/date.ts` (`MESES`, `DIAS_CORTOS`).

**Consecuencias:**
- El mismo concepto se escribe distinto en dos pantallas sin que nadie lo note.
- **Los textos no llevan tilde** (`Habitos`, `contrasena`, `Sueno`), porque se adoptó la regla
  de evitar acentos en el código fuente. Eso es aceptable en un identificador; en un texto que
  el usuario lee, es un error ortográfico visible.
- Cambiar una palabra obliga a buscarla por todo el árbol.

---

## Plan: primero centralizar, después traducir

### Paso 1 — Centralizar (Sprint 2)

Un único módulo `src/constants/textos.ts`, con claves agrupadas por pantalla:

```ts
export const textos = {
  login: {
    titulo: 'Hábitos Saludables',
    subtitulo: 'Tu progreso diario, en un solo lugar',
    errorCamposVacios: 'Completa todos los campos',
    errorCredenciales: 'Credenciales incorrectas',
  },
  registros: {
    errorDuplicado: 'Ya existe un registro de este hábito para esa fecha.',
    exitoMetaCumplida: 'Registro guardado. ¡Meta cumplida!',
  },
  // ...
} as const;
```

Este paso, por sí solo, ya resuelve el problema de las tildes: los textos pasan a estar en un
archivo donde escribirlos correctamente no genera ninguna duda, y el código sigue sin acentos
en sus identificadores.

### Paso 2 — Traducir (solo si hace falta)

Si el producto necesitara un segundo idioma, se adopta `i18n-js` + `expo-localization`, y
`textos.ts` se convierte en el diccionario del idioma por defecto. El paso 1 es lo que hace que
el paso 2 sea barato; **no se adelanta la librería antes de tener el requisito.**

---

## Reglas (vigentes desde que se complete el paso 1)

- **Ningún texto visible al usuario escrito dentro de una pantalla.** Todo viene de `textos.ts`.
- Las claves se nombran por pantalla y por intención: `login.errorCredenciales`,
  `metas.errorMetaActivaExistente`.
- Los mensajes de error de negocio se declaran **junto a la regla que los produce**, en
  `AppContext`, no duplicados en cada pantalla que los muestra.
- Fechas y números se formatean con las utilidades de `utils/date.ts`, nunca concatenando a mano.
- La pluralización no se hace con concatenación: si el texto cambia con la cantidad, se declaran
  las dos variantes (`1 día` / `N días`).

---

## Nota sobre RTL

La app **no soporta idiomas de derecha a izquierda** hoy, y no está previsto. Si algún día lo
necesitara, hay que sustituir todos los `marginLeft` / `marginRight` y `textAlign: 'left'` por
sus equivalentes lógicos (`marginStart`, `marginEnd`). A favor del futuro: la app usa
mayoritariamente `gap` y `flexDirection`, que ya son direccionales por defecto.

## Checklist

- [ ] Ningún literal de texto visible dentro de `screens/` o `components/`.
- [ ] Todos los textos del usuario con la ortografía correcta, tildes incluidas.
- [ ] Fechas y números formateados con las utilidades comunes.
- [ ] Traducciones largas no desbordan (probar con el texto más largo del diccionario).
